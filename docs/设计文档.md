## 1. 这份文档要解决什么

### 1.1 任务的真实性质

任务书第一句：

> 项目：宏达精密 · 本地排产助手（简化版 APS）
> 形式：2~3 人一组；也可以一人独立完成
> 周期：**3 周，6 个节点**
> 提交：每组一个 **Git 仓库**，节点到期提交到指定位置
> 评分：**六个节点累计 100 分 + 加分 10 分**

**这不是一份"给客户的设计文档"，是一份"给自己和评分用的开发计划"。**

### 1.2 六个节点（任务书表 2 原文）

| 节点 | 名称 | 周次 | 工时（快/一般/卡住） | 分值 | 核心里程碑 |
|---|---|---|---:|---:|---|
| N1 | 工作区与 Git 环境 | 第 1 周前半 | 0.5h / 1~2h / 3h | 10 | 代码进版本控制，能回滚 |
| N2 | 产品设计开发说明书 | 第 1 周后半 | 1.5h / 2~4h / 6h | 15 | 说清"做什么、不做什么" |
| N3 | 前端图片（UI 稿） | 第 2 周前半 | 1h / 2~3h / 4h | 10 | 三张图 + 交互说明 |
| N4 | 后端开发 | 第 2 周后半 | 3h / 5~8h / 15h | 25 | 命令行跑通，出四件产物 |
| N5 | 前后端打通 | 第 3 周前半 | 1.5h / 3~4h / 6h | 20 | 浏览器里全流程走通 |

**本文档覆盖 N2（主体）+ N1/N3/N4/N5/N6 的设计部分**，N6 的实测报告另出。

### 3.2 【新发现·决定性】磨工序全部点名 `GRD-01`，GRD-02 永远用不上

**这是本次重新通读最重要的发现，直接推翻上一版的核心结论。**

逐字核对工艺表：

| 产品 | 磨工序原文 | 性质 |
|---|---|---|
| 阀体A | `磨（GRD-01）25` | **点名某台** |
| 阀体B | `磨（GRD-01）20` | **点名某台** |
| 阀芯C | `磨（GRD-01）35` | **点名某台** |
| 法兰D | 无磨工序 | — |
| 端盖E | 无磨工序 | — |

**5 个产品里 3 个有磨工序，全部写 `GRD-01`，没有任何一个写 `磨（GRD）` 组形式。**

对比同表其他工序：

| 写法 | 性质 | 举例 |
|---|---|---|
| `车（LAT）` | 组（3 台任选） | LAT-01/02/03 |
| `铣（CNC）` | 组 | CNC-01/02/03 |
| `钻（DRL）` | 组 | DRL-01/02 |
| `下料（SAW-01）` | **点名**（但组内只有 1 台，无区别） | SAW-01 |
| `铣（CNC-03）` | **点名**（该机停机） | CNC-03 |
| `磨（GRD-01）` | **点名**（组内有 2 台，**区别巨大**） | GRD-01 |

**后果（实算，`_复算2` C 节）**：

```
磨负荷 = 12,350 min（阀体A 3,000 + 阀体B 2,350 + 阀芯C 7,000）
GRD-01 单台窗口容量 = 5,760 min（6 天 × 960）
缺口 = 6,590 min = 6.86 天
```

**GRD-02（闲置）无论启不启用，在这份台账的工艺路线下都用不上。**
所以上一版设计里「启用 GRD-02 把磨从 12.9 天压到 6.4 天」这个结论，**在这份数据上不成立** —— 因为磨是点名的，不是组。

> **这条要么是台账笔误（该写 `磨（GRD）`），要么是真实的工艺约束（外圆磨 M1432 与平面磨 M7130 加工对象不同，不能互换）。**
> **必须问客户（新 Q6），不能自己决定。** 见 §8 Q6 的三种处置。

### 3.3 设备四态（必须分开，不能一律"不可用"）

| 状态 | 原文 | 机台 | 语义 | 排程处理 | 能否一问就开 |
|---|---|---|---|---|---|
| `available` | 在用 | 9 台 | 正常可用 | 进调度池 | — |
| `down` | 停机维修（11/8 起） | CNC-03 | 暂时不可用，**恢复日未知** | 排除 | 否，得等维修 |

> 注意 HT-01 的原文是 **「在用（外协，不计本厂）」**——同时含「在用」和「外协」。
> 分类时**必须先判"外协"再判"在用"**，否则会把外协炉当成可用产能。（这是本次新发现的一个解析陷阱。）

### 3.4 【新发现】台账整理日期是周日

`订单!A1` 原文：「宏达精密 · 待排产订单（计划员小李整理，**2026-11-08**）」。

`2026-11-08` 是**周日**。而手册 §3.4 规定「本周起始日取**最近的周一**」：

```
2026-11-08 是周日 → 下一个周一是 2026-11-09
```

**所以排程原点 = 2026-11-09（周一）08:00**，与 PPT 第 13 页一致。
但如果代码按「取当周周一」算（`date - weekday()`），会得到 `2026-11-02`，**整周错位**。必须写成 `(7 - weekday) % 7` 向前找。

### 3.5 【新发现】第 18 行是注释行，不是订单

`订单!A18`：「注：交期一栏有的填了日期，有的写了字，按实际意思来。」

**按行遍历会把这一行当成订单**（单号含中文、数量空、交期空），进闸门或被静默丢弃。
必须用「单号匹配 `^HD` 或纯数字」做过滤，或跳过「单号含中文」的行，并记入体检报告。

### 3.6 【新发现】`11月12日` 缺年份

`订单!D4` = `11月12日`，没有年份。必须补 `2026` 才能算出交期。
补错年份（如 2025）会让这单直接判定「已过期」。**记入体检报告：「交期缺年份，按台账整理年 2026 补齐」。**

### 3.7 【新发现】113 的「先做一半」是本周一半，不是拆成两单

`订单!G16` = 「先做一半，剩下的下周」。
PPT 第 17 页处理方式是「拆两单或合并（要问）」，但工艺表 r9 备注给了明确口径：

> 备注里的口头规则：…；『先做一半』的**按一半数量算**。

所以 **本周按 35 ÷ 2 = 17.5 件排**，不拆成两张订单。下半批不进本周窗口。
需要客户确认「17.5 件」是否可以（机加工通常允许半件/小数，但排程表上要写清）。→ **Q5**

### 3.8 【新发现】HT-01 无设备号

`设备!A14` 是空单元格，但 B14 = `HT-01`。按「设备号」列判断行数会漏掉这一台。
**必须按「编号」列判断**，这是 12 台的来源。

### 3.9 其余 5 项（沿用 PPT 第 17 页并补充到位）

| # | 项 | 位置 | 处理 |
|---|---|---|---|
| 9 | 工时单位是「分钟/件」 | `工艺路线!A1`、`A10` | `时长 = 单件工时 × 数量`。若当每批，120 件阀体A 只算 180 min 而非 21,600，**总量差 30 倍** |
| 10 | `LAT-03` 三班 | `设备!E8` | 全厂口径两班 08–24。**按两班算**（假设 A1），不偷加产能。若按三班：车容量 17,280 → 25,920 |
| 11 | CNC-03 恢复日缺失 | `设备!F5`「停机维修（11/8 起）」 | 只知起始不知结束 → **排除整周**。若周内恢复则铣容量增加 |

## 5. 客户澄清三条与落地

任务书/PPT 里客户给了三条明确口径（PPT 第 19 页「客户原话」+ 交接要求）。

| # | 客户要求 | 落地为 | 可校验形式 |
|---|---|---|---|
| **C1** | 「这周每天每台机到底干什么」 | 周排程表 + 甘特图 | 每台机每天每道工序有起止时间，校验 H4 不重叠 |
| **C2** | 「哪几单要赶不上」 | 交期风险清单 | 单号/交期/预计完工/差几天/卡在哪台机，每条能反查到工序 |
| **C3** | **「阀芯C 两道工序之间的间隔不能超过 30 分钟」** | **附加条件 H5**（PPT 四条硬约束之外） | `0 ≤ start(磨) − end(车) ≤ 30`，逐子批校验；未达成判 `PASS_WITH_WARN`，不阻断交付 |

### 5.1 C3 的语义必须钉死（三种解读）

客户原话：**「阀芯C 里的备注意思是两道工序之间的间隔不能超过 30 分钟」**。

「间隔」有三种数学解释，**本设计明示采用 (a)**：

| 解读 | 形式 | 可行性（车 40 / 磨 35 min/件） | 采纳 |
|---|---|---|---|
| **(a)** 前道完工 → 后道开工的**等待** | `0 ≤ start(磨) − end(车) ≤ 30` | ✅ 可行 | ✅ **采用** |
| (b) 两道工序**开工**之差 | `0 ≤ start(磨) − start(车) ≤ 30` | ❌ **无解**：车单件 40 > 30，磨最快也要车开工后 40 min | ❌ |
| (c) 两道工序**完工**之差 | `0 ≤ end(磨) − end(车) ≤ 30` | ✅ 可行，但磨须延后 5 min 起（35 < 40） | 备选 |

**解读 (b) 数学上无解**，这证明该歧义不是咬文嚼字——猜错会让整条约束不可行。→ **Q7**

**客户原话与台账的对应关系**：`工艺路线!H5` 的备注原文是「**磨是瓶颈，别排太散**」。
客户说的「间隔不超过 30 分钟」是对这句备注的**量化解释**，把它从人话变成可校验的数值约束。

### 5.2 C3 的产能代价（这是本设计的技术核心，见附录 D）

阀芯C 确定量 200 件（103 的 120 + 104 的 80；110 数量待定）：

**件级严格连续（口径①）**

```
节拍 = max(车 40, 磨 35) = 40 min/件
总跨度 = 200 × 40 = 8,000 min = 8.33 天（单台磨）
单台磨窗口 = 5,760 min
→ 超窗 2,240 min = 2.33 天   ★ 物理不可行
```

**子批流水（口径②，批内连续、批间可断）**

| 子批 L | 批数 | 单批磨床空等 | 全部空等 | 磨有效容量（1台） | 磨总缺口 |
|---:|---:|---:|---:|---:|---:|
| 10 | 20 | 85 | 1,700 | 4,060 | **8,290** |
| **20** | **10** | **135** | **1,350** | **4,410** | **7,940** |
| 40 | 5 | 235 | 1,175 | 4,585 | 7,765 |
| 100 | 2 | 535 | 1,070 | 4,690 | 7,660 |
| 200 | 1 | 1,035 | 1,035 | 4,725 | 7,625 |

```
有效容量 = 窗口容量 − C3 造成的磨床空等
真实缺口 = 磨负荷 − 有效容量
```

**关键结论（三点）**：

1. **空等随 L 增大而减小**（首件等待 40 min 只付一次，批数越少付得越少）。
   所以「子批越小越好塞」是错的——**小批在灵活性上赢，在产能上输**。
2. **L=200（整单一批）同样满足 C3**（批内件间间隙恒为 5 min ≤ 30），不是只有拆批才行。
3. **单台磨 + C3，缺口 7,940 min（L=20）= 8.27 天**。
   这不是「排得散不散」的问题，是产能根本不够。

### 5.3 C3 与产能结论的闭环验证

| 步骤 | 算式 | 结果 |
|---|---|---|
| 1. 磨净加工负荷 | 阀体A 3,000 + 阀体B 2,350 + 阀芯C 7,000 | 12,350 |
| 2. C3 造成磨床空等（L=20） | (40 + 19×5) × 10 批 = 135 × 10 | 1,350 |
| 3. 磨床有效容量 | 5,760 − 1,350 | **4,410** |
| 4. 磨真实缺口 | 12,350 − 4,410 | **7,940** |
| 5. 校验闭合 | 4,410 + 7,940 | 12,350 ✅ |

**逐位可对，不存在"文档一个数、算法另一个数"。**

## 8.5 风险清单的四种类型（必做区分）

客户 C2 要「哪几单要赶不上」。但 13 张可排订单里，**6 张的交期在窗口外**（11-18 之后）。
若不区分类型，会把它们全标成"延期"，老板拿着这份清单去跟客户说"我有 10 单迟到"，**是错的**。

| 类型 | 英文枚举 | 判据 | 是否真延期 | 老板怎么用 |
|---|---|---|---|---|
| 🔴 **延期** | `delayed` | 已排入且 `planned_end > 交期@17:00` | ✅ 是 | 打电话跟客户解释 |
| 🟡 **预警** | `at_risk` | 已排入且余量 < 1 个班次（480 min） | 否 | 提前确认物料 |
| ⚪ **未排入本周** | `not_scheduled_in_horizon` | 未排入且交期在窗口后 | ❌ **否** | 下周再说 |
| ⚫ **排不进** | `unplannable` | 受产能 / H5 限制无法安排 | — | 需决策（加机器/顺延） |

**判定为纯函数**（`report.py` 内，不依赖排程器）：

```python
def decide_status(planned_end, due, qty_total, qty_planned, opts):
    if qty_planned == 0:
        if due is None:                      return "unplannable"
        if due > opts.horizon_end:           return "not_scheduled_in_horizon"
        return "unplannable"
    if planned_end is None:                  return "unplannable"
    if qty_planned < qty_total:              return "at_risk"
    if due is None:                          return "ok"
    if planned_end > due_at(due, DUE_HOUR):  return "delayed"
    if (due_at(due, DUE_HOUR) - planned_end).total_seconds()/60 < AT_RISK_MINUTES:
        return "at_risk"
    return "ok"
```

## 9. 三条硬约束 + C3 的可校验形式

详见附录 C。摘要：

| # | 约束 | 校验形式 | 违反时 |
|---|---|---|---|
| H1 | 每道工序恰好一次 | 期望集合 vs 实际集合，差集 = 漏排，重数 >1 = 重排 | 阻断交付 |
| H2 | 机台与工时与工艺一致 | `machine ∈ 路线允许集` 且 `duration == 单件工时 × 数量` | 阻断 |
| H3 | 同订单工序不倒序 | 按 seq 排序后 `start(i+1) ≥ end(i)` | 阻断 |
| H4 | 同一台机时间不重叠 | 按机台分组、按 start 排序、相邻比较 | 阻断 |
| **H5** | **阀芯C 车→磨 ≤30 min** | `0 ≤ start(磨) − end(车) ≤ 30`（按子批） | 阻断；未排入记 SKIP |

**0 违反才继续渲染。** 这是任务书 N4 的核心验收点，也是红线（校验器不能由 AI 判断）。

## 11. 结论

# ✅ 可开发

**判定依据**：

1. **输入已完整通读并复算**：4 个文件（2 份 docx + 1 份 pptx + 1 份 xlsx）逐字导出，台账三轮独立复算，所有数字可追溯（`文件/_复算1~3`）。
