## v0.1-skeleton · 后端骨架

**能做什么**：命令行跑通，出排程结果。

```
config.py + core/ 六个模块 + run.py
```

此时没有前端、没有单测。排程是「窗口截断」式——本周排不完就标成排不进。

---

## v0.2-web · 前后端打通（N5）

**能做什么**：双击 `index.html` 走浏览器端，`python server/app.py` 走后端，两条路都能出结果。

```
+ frontend/（index.html / app.js / engine.js / xlsx-lite.js / style.css）
+ server/app.py（标准库 http.server，3 个 API）
```

engine.js 与 core/ 的数字口径已经对齐。但排程仍受窗口容量限制。

---

## v0.3-tested · 单测与一致性

**能做什么**：有了自动化的质量保障。

```
- 删除临时脚本 _t1~_t5.py
+ tests/test_core.py（46 条单测）
+ frontend/test/parity_check.js（前后端数字逐项对比）
```

---

## v0.4-aligned · 口径全面对齐

**能做什么**：前后端结论完全一致，可以放心交付。

三个关键修正：

1. **H5 改为警告级**：硬约束只有 H1~H4，H5（阀芯C 流水 ≤30min）是客户澄清的条件，未达成判 `PASS_WITH_WARN` 而非 `FAIL`
2. **排程可向后延伸**：窗口 6 天是「本周窗口」判定，不是排程硬上限
3. **allow_mill_substitute 默认 true**：与前端 `allowSwap` 默认值对齐

同时设计文档、UI 截图、原始材料全部入库。

---

## v1.0-delivery · 交付版

**能做什么**：完整交付。

七件产物：

```
out/排单表.xlsx       每天每台机干什么，可打印贴墙
out/甘特图.html       单文件，断网可用
out/风险清单.xlsx     哪几单赶不上、卡在哪台机
out/体检报告.md       台账里哪些数不能用
out/校验报告.txt      五条约束逐条结果
out/交接说明.md       怎么重跑 / 假设 / 局限
out/需求确认单.md     我理解的三件事 / 客户不要的 / 问答
```

新增能力：

- **需求确认单 + 交接说明**（程序生成，随参数自动更新）
- **数据源适配层** `datasource.js`（file:// 与 http 统一）
- **三件套冒烟测试**（smoke / smoke_server / smoke_e2e）
- **失败时旧产物归档** `_stale/`（避免旧表被当成新版贴墙）

## 怎么用这些标签

```bash
# 看所有版本
git tag -l -n1

# 切到某个版本（只读查看，别在上面直接改）
git checkout v0.2-web

# 回到最新
git checkout main

# 在某个版本上开分支做修改
git checkout -b fix-on-v1 v1.0-delivery

# 看两个版本之间改了什么
git diff v0.3-tested v1.0-delivery --stat
```

**注意**：`git checkout <tag>` 会进入 detached HEAD 状态，此时提交不属于任何分支。要么只是看看（然后 `git checkout main` 回来），要么明确 `git checkout -b <新分支名>`。
