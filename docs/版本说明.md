## v0.1-skeleton · 后端骨架

**能做什么**：命令行跑通，出排程结果。

```
config.py + core/ 六个模块 + run.py
```

此时没有前端、没有单测。排程是「窗口截断」式——本周排不完就标成排不进。

## v0.2-web · 前后端打通（N5）

**能做什么**：双击 `index.html` 走浏览器端，`python server/app.py` 走后端，两条路都能出结果。

```
+ frontend/（index.html / app.js / engine.js / xlsx-lite.js / style.css）
+ server/app.py（标准库 http.server，3 个 API）
```

engine.js 与 core/ 的数字口径已经对齐。但排程仍受窗口容量限制。

## v0.4-aligned · 口径全面对齐

**能做什么**：前后端结论完全一致，可以放心交付。

三个关键修正：

1. **H5 改为警告级**：硬约束只有 H1~H4，H5（阀芯C 流水 ≤30min）是客户澄清的条件，未达成判 `PASS_WITH_WARN` 而非 `FAIL`
2. **排程可向后延伸**：窗口 6 天是「本周窗口」判定，不是排程硬上限
3. **allow_mill_substitute 默认 true**：与前端 `allowSwap` 默认值对齐

同时设计文档、UI 截图、原始材料全部入库。

## v1.1-rules · 排程口径逐位对齐（当前）

v1.0 打标后发现两处前端与后端结果不一致的根因，修复后重新打标：

1. **银行家舍入**：Python `round()` 是四舍六入五取偶，`15×17.5=262.5 → 262`；
   前端 `Math.floor(x+0.5)` 会得 263。在 .5 处差 1 分钟，逐工序累积后整天错位。
2. **排序规则**：fifo/spt/mwkr 的次键与 `core/solver.py _sort_orders` 严格对齐；
   edd/prio 退出默认候选集（任务书表 8 只认三种规则）。

新增：

- **「急单·无交期」状态**（`urgent_no_due`）：备注写「客户催，越早越好」的单
  没有硬交期，报「准时」等于给客户假的确定；现在单独成状态，只报预计完工
- **建议动作量化**：不只说"卡在 GRD-01"，还给出该组缺几天、放大 lot-size 能省几天
- 修复 server 静态资源误发 `Content-Disposition: attachment` 导致首页被下载

## 怎么用这些标签

```bash
# 看所有版本
git tag -l -n1

# 切到某个版本（只读查看，别在上面直接改）
git checkout v0.2-web

# 回到最新
git checkout main

# 在某个版本上开分支做修改
git checkout -b fix-on-v1 v1.1-rules

# 看两个版本之间改了什么
git diff v0.3-tested v1.1-rules --stat
```

**注意**：`git checkout <tag>` 会进入 detached HEAD 状态，此时提交不属于任何分支。要么只是看看（然后 `git checkout main` 回来），要么明确 `git checkout -b <新分支名>`。
