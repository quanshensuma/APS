════════ 任务 B1 · 补齐「交接说明」产物 ════════
【为什么】PPT 第9页要求交六件，第21页写「四样缺一不可，只交前两样是做了个模型，
不是交付」，第26页把「没有交接说明」列为直接不及格。现在完全没有这份产物。

【做什么】在 core/report.py 新增 write_handover_md()，run.py 第 7 步与另外四件一起调用，
输出 out/交接说明.md。内容四块，写给不懂技术的计划员，禁止出现 solver / CP-SAT / Operation：

1. 怎么重跑——台账放哪、敲哪条命令、产物在哪；4~6 个常用参数各写「什么时候该用它」
   （--enable-grd02 / --morning-as-group / --enable-cnc03 / --lot-size N /
   --allow-mill-substitute）；先看校验报告.txt 的「结果：」一行，再看风险清单
2. 假设清单 ≥5 条，每条必须两半：「假设是什么」+「不成立会怎样」
   覆盖：三班车床按两班、换型调机未建模、人员资质未建模、工时按标准值、
   只排本周 6 天周日不排、磨点名 GRD-01、HT-01 外协不计本厂产能
3. 已知局限：不建模换型（实际完工会晚 10~30%）、不建模人员资质、
   插单只预演不自动重排、阀芯C「车间隔 ≤30 分钟」为口头澄清未签字
4. 什么条件下不能信：CNC-03 停机期间禁换机台会大量排不进、

参数/假设/局限三处内容从 config.py 与 RunOptions 取，不在模板里复制会脱钩的副本；
PASS_WITH_WARN 时仍要生成；不引入新依赖。

4. 换一份改了数量的台账重跑，文中引用的数量/窗口/机台数跟着变

════════ 任务 B2 · 补齐「需求确认单」产物 ════════
【为什么】PPT 第9页第 1 件交付物就是需求确认单（一页纸 = 我理解的三件事 + 我问到的答复），
第16页要求「从 10 个必问问题里挑 5 个」，自检点是「每个答复是否改变了你的某个判断」。

【更要紧的一条】config.py 的 FLOW_CONSTRAINTS 有一条定量约束：
阀芯C 车完工→磨开工等待 ≤30 分钟，source 标为「客户 2026-10-28 澄清 C3」，confirmed: False。
但「30 分钟」在 27 页 PPT、APS工具开发任务书.docx、APS工具开发项目手册.docx 里
全部查不到出处。这条未签字的口头约束现在决定了整个交付结论的性质
（磨床缺口 6,590 → 7,940 min，差约 1.4 个工作日）。必须让它对客户可见。

【做什么】新增 core/confirm.py 生成 out/需求确认单.md，固定五段：
① 我理解的三件事（恰 3 条，每条一句，取自 PPT 第7页客户原话）
② 客户明确不要的（装一堆东西 / 必须联网 / 按年付费）
③ 恰 5 个问答，三列表格：问题 | 客户答复 | 这个答复改变了什么判断
④ 未确认事项单列一节：把 FLOW_CONSTRAINTS 里 confirmed: False 的全列出，
   每条写当前取值、来源、已按此实现、客户确认后改哪里
⑤ 待客户签字栏（姓名 / 日期 / 逐条打勾）

5 个问题从这批里挑最能影响结果的：时间原点、班次口径（LAT-03 是否 3 班）、
交期口径（当日 17:00 还是收工前）、「尽快」「月底前」怎么算、
CNC-03 停几天且期间能否换机台、GRD-02 能否分担磨、
阀芯C「别排太散」具体多少分钟、HD-2026-110 数量何时给、
HD-2026-106 重复两次是两单还是一单、HD-2026-113「先做一半」按 17.5 件对不对。
代表答的客户答复若暂无答复，写「待客户确认」，严禁编造。

【硬约束】不许出现第二份「30 分钟」字面副本，确认单取值从 config.py 读取，单一数据源；
不改 H5 阈值与判定逻辑；对客户的文档不许出现代码文件名与内部术语。

【验收】
1. 单页 A4 放得下，三件事恰 3 条、问答恰 5 条
2. 每个问答第三列都有内容，空值即不通过（写不出来说明该换问题）
