【范围】宏达精密排产助手前端。只改 web/（index.html / app.js / style.css），
不要碰 run.py、core/、web/app.py——后端由另一个会话并行改，且它照同一份契约输出。
web/engine.js 是纯 JS 排程引擎，本段一律不改它的计算逻辑，数字全部来自 engine.js。

【项目现状】纯浏览器、零依赖、不需构建；app.js 只做渲染；
后端三个接口 /api/health、/api/generate、/api/download/<name>。

【并行前提】后端正在加三件东西：交接说明产物、需求确认单产物、产物新鲜度归档。
字段名以契约（summary / verify.hardViolations / verify.softViolations / verify.resultCn /
artifacts / staleArchived / handover / confirm）为准。
要求：字段缺失时优雅降级（该面板隐藏或显示「暂无」），不得抛错、不得白屏。
这一点很重要——后端可能比你晚落地，前端不能等地基。

════════ 任务 F3 · 失败态与产物新鲜度 ════════
【问题】前端失败态只显示一条错误横条，产物区仍可能保留上一次成功生成的下载链接与预览，
用户分辨不出这是这次的还是上次的。

【做什么】
1. 每次点「生成」先清空/置灰产物区，进入「生成中」，旧链接不可点
2. 失败时：错误条保留 + 产物区替换为「本次未生成任何排程产物」明确空态；
   若后端告知已归档，附一句「上一版已归档，仅供追溯，请勿打印贴墙」，
   并给归档文件一个「仅查看」样式的次要入口（视觉必须弱于正常下载）；
   正常下载区不得出现带 .stale 的链接
3. 成功时（含 PASS_WITH_WARN）正常展示五件产物；PASS_WITH_WARN 用黄色提示条：
   「硬约束 0 违反，可打印；流水条件未达成，须向客户说明代价」，严禁用红色失败样式
4. 页面顶部常驻显示本次结果生成时间与数据源文件名，便于判断是不是最新一版

【硬约束】不在前端解析或臆造校验结论，一律用后端 result 字段决定配色与文案。
