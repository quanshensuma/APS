## ① 用户与场景

任务书要求：**至少 2 个角色（计划员/老板）**。

### 角色 1：计划员 · 小李

| 项 | 内容 |
|---|---|
| 是谁 | 宏达精密唯一的生产计划员 |
| 在什么情况下用 | **每周一上午**，拿到汇总的待排产订单，要排出这一周每台机干什么 |
| 现在怎么做 | 用 Excel 手工排，约 **2 小时**，排完打印贴墙 |
| 痛在哪 | ① 插单就乱：客户一催就得全表重来，一小时起<br>② 交期靠拍：客户问"下周能出不"，只能答"尽量"<br>③ 排完撞机：同一台机两个活同时干，车间打电话来骂 |
| 要工具给什么 | **这周每天每台机干什么** + **哪几单要赶不上** |
| 会不会技术 | **不懂技术**，要求"办公室电脑上点一下能出来" |
| 场景触发的操作 | 拖入台账 → 点生成 → 看风险清单 → 打印排程表贴墙 |

### 角色 2：老板 · 张工

| 项 | 内容 |
|---|---|
| 是谁 | 宏达精密生产负责人（客户电话里说话的人） |
| 在什么情况下用 | ① 客户催单时，要立刻回答"能不能出"<br>② 每周看整体产能负荷，决定要不要加机器/加班<br>③ 插急单时，判断"挤掉哪张单" |
| 现在怎么做 | 靠计划员口头汇报 + 凭经验判断 |
| 痛在哪 | 交期不敢承诺；不知道瓶颈在哪台机；插单决策没有依据 |
| 要工具给什么 | **哪几单要晚、卡在哪台机**（这句话他在电话里说了两遍） |
| 会不会技术 | 不懂，但看得懂表格和数字 |

### 两个角色的诉求差异（这是设计关键）

| | 小李（计划员） | 张工（老板） |
|---|---|---|
| 关心粒度 | 每台机、每道工序、几点开始 | 哪几单、晚几天、卡哪台机 |
| 看的东西 | 周排程表（打印）、甘特图 | 交期风险清单 |
| 用工具时的心情 | 「别让我重排两小时」 | 「给我一个敢答应客户的依据」 |
| 因此需要 | 一键重跑、字段齐全、能打印 | 一句话说清风险、能指着机台说话 |

→ **UI 三类页面正好对应**：结果页（小李看）、风险页（张工看）、主界面（小李操作）。

│                     │                     ┌────────────┐         │
│                     │                     │  checker   │◄──── 独立 │

│              ┌────────────────────────────────────────┐          │

### 数据形态的变化（这条链上每一步的数据长什么样）

| 步骤 | 输入 | 输出 | 关键字段 |
|---|---|---|---|
| reader | `.xlsx` 文件 | `raw = {orders[], machines[], routes[]}` 原样 | 保留单元格坐标（`订单!D3`） |
| cleaner | `raw` | `clean = {orders[], machines{}, routes{}, issues[], blocked[]}` | `id_raw→id`、`due_raw→due`、`qty_raw→qty` |
| instance | `clean` | `ops[]`，每个 `(order, seq)` 一条 | `duration = min_per_unit × qty` |
| solver | `ops[]` + 机台池 | `sched[]`，每个 op 有 `machine/start/end` | 轴分钟 |
| checker | `sched[]` + `clean` | `report{h1..h5, ok}` | 违规列表 |
| report | 全部 | 4 个文件 | 挂钟时刻 |

**每一步都落 JSON**（`data/clean.json`、`data/sched.json`），便于单独重跑和人工核对。

## ④ 数据字典

任务书要求：**三个 sheet 每个字段：含义、类型、必填、脏数据风险，字段全覆盖**。

### ④.1 `订单` sheet（7 列）

| 列 | 单元格例 | 含义 | 类型 | 必填 | 脏数据风险 |
|---|---|---|---|---|---|
| A `单号` | `订单!A3` = `HD-2026-101` | 订单标识 | str | ✅ | 🔴 **三种写法**：`HD-2026-101` / `HD2026102` / `104`；🔴 **r8 与 r14 重复**（25 vs 40 件）；🔴 **r18 是注释行**（含中文） |
| B `客户` | `客户甲` | 客户名 | str | ✅ | 🟡 同一客户多种写法（未见，但需防） |
| C `接单日期` | `2026/11/3` | 下单日 | date | ❌ | 🔴 **四种格式**：`2026/11/3`、`2026-11-03`、`2026.11.4`；🔴 **r11 空**；🟡 `openpyxl` 读出可能是 **str 不是 datetime** |
| D `交期` | `2026-11-10` | 承诺交货日 | date | ❌ | 🔴 **五种形态**：日期 / `11月12日`（缺年）/ `尽快` / `月底前` / **空**；🟡 交期口径未写明时刻（按 17:00） |
| E `产品` | `阀体A` | 产品族 | str | ✅ | 🟡 是"族"不是料号，多规格工时相同（假设 A8） |
| F `数量` | `40` | 件数 | num | ✅ | 🔴 **r12 空**（备注"等客户确认"）；🟡 可能为小数（113 的 17.5） |
| G `备注` | `急单，张工说的` | 口头规则 | str | ❌ | 🔴 **藏 5 条业务规则**：急单/客户催→优先级、材料到货→release、先做一半→拆批、和上批一起做→合并建议 |

### ④.2 `设备` sheet（6 列）

| 列 | 单元格例 | 含义 | 类型 | 必填 | 脏数据风险 |
|---|---|---|---|---|---|
| A `设备号` | `M-01` | 内部序号 | str | ❌ | 🔴 **r14 空**（HT-01 无设备号）→ **不能按此列判行数** |
| B `编号` | `CNC-01` | 机台编号（**排程主键**） | str | ✅ | 🟡 与工艺路线的括号内标识必须一致 |
| C `型号` | `立式加工中心 VMC850` | 设备型号 | str | ❌ | 🟢 仅用于展示 |
| D `可做工序` | `铣、镗` | 能干的工序 | str[] | ✅ | 🔴 **多值用「、」分隔**，需 split；🟡 决定机台组的成员 |
| E `每日班次` | `2 班` | 班次数 | int | ✅ | 🔴 **LAT-03 是 `3 班`**，与全厂两班冲突（假设 A1）；🟡 含中文"班"需提取数字 |
| F `状态` | `在用` / `停机维修（11/8 起）` / `闲置` / `在用（外协，不计本厂）` | 可用性 | enum | ✅ | 🔴 **四态必须分开**；🔴 **HT-01 同时含「在用」和「外协」**→ **必须先判外协再判在用**，否则误当可用产能；🔴 CNC-03 只知起始不知恢复日 |

### ④.3 `工艺路线` sheet（8 列）

| 列 | 单元格例 | 含义 | 类型 | 必填 | 脏数据风险 |
|---|---|---|---|---|---|
| A `产品` | `阀体A` | 产品族（关联订单） | str | ✅ | 🟡 订单里的产品必须能在此找到，否则该单进闸门 |
| B~F `工序1~5` | `铣（CNC-03）60` | 工序 + 机台 + 单件工时 | str | ✅(至少 B) | 🔴 **一格里塞了三样东西**，需正则拆：`(.+?)（(.+?)）(\d+)`；🔴 **括号内有两种含义**：`LAT`=组、`CNC-03`=点名；🔴 **磨全部点名 GRD-01**（见 §3.2）；🟡 工序数 2~5 不等，空列要跳过 |
| G `单件工时合计` | `180` | 每件总工时 | int | ✅ | 🟢 已复算：五产品全部等于逐工序求和，**可用作校验锚点** |
| H `备注` | `磨是瓶颈，别排太散` | 工艺说明 | str | ❌ | 🔴 **r5 备注是客户 C3 的来源**（"别排太散"→间隔≤30min）；🟡 r9/r10/r11 是全局规则不是某产品的备注 |

### ④.4 三个 sheet 之外的"隐式字段"

| 隐式项 | 来源 | 为什么必须建模 |
|---|---|---|
| 排程原点 | `订单!A1` 台账整理日 `2026-11-08`（周日）→ 最近周一 `11-09` | 差一周就整周错位 |
| 班次时段 | 全厂 08:00–24:00 两班 | 分钟→挂钟换算的基准 |
| 周日不排 | 手册 §3.4 | 6 天窗口的来源 |
| 交期时刻 | 手册 §3.4「交期 17:00」 | 同日 18:00 完工算不算延期 |

**错误返回**（`400`）

```json
{"ok": false, "error_code": "NOT_XLSX",
 "error_msg": "请上传 .xlsx 文件（当前文件不是 Excel 工作簿）",

```

| `error_code` | 触发 | `error_msg` |
|---|---|---|
| `NOT_XLSX` | 后缀不是 `.xlsx` 或魔数不对 | 请上传 .xlsx 文件 |
| `MISSING_SHEET` | 缺 `订单`/`设备`/`工艺路线` | 缺少工作表「工艺路线」，请检查台账 |
| `HEADER_MISMATCH` | 表头名对不上 | 第 2 行表头应为「单号/客户/…」，实际为「…」 |
| `EMPTY_DATA` | 表格无数据行 | 台账里没有可识别的订单行 |
| `VERIFY_FAILED` | 校验未过 | 校验未通过（H4 撞机 2 处），请查看体检报告 |
| `INTERNAL` | 其他异常 | 内部错误，请把日志发给我们 |

### ⑤.2 `GET /api/download/<filename>`

| 项 | 内容 |
|---|---|
| 路径参数 | `filename` ∈ `排单表.xlsx` / `甘特图.html` / `风险清单.xlsx` / `体检报告.md` |
| 返回 | `200` + 文件流，`Content-Disposition: attachment; filename*=UTF-8''<urlencoded>` |
| 关键 | **中文文件名必须用 RFC 5987 的 `filename*`**，否则下载乱码（任务书 N5 明确点名） |
| 错误 | `404` → `{"ok":false,"error_code":"FILE_NOT_FOUND","error_msg":"文件不存在或已被清理"}` |

### ⑤.3 `GET /api/health`

| 项 | 内容 |
|---|---|
| 用途 | 前端启动时探活，避免白屏 |
| 返回 | `{"ok":true,"version":"1.0.0","python":"3.11.7","openpyxl":"3.1.5"}` |
| 错误 | 服务没起 → 前端显示「服务未启动，请先运行 python web/app.py」 |

## ⑥ 假设与边界（≥5 条，每条写"不成立会怎样"）

| # | 假设 | 不成立会怎样 | 验证方式 |
|---|---|---|---|
| **A1** | `LAT-03` 的「3 班」按 **2 班**算（全厂口径 08–24） | 车床日产能少 480 min/台，周容量 17,280 → 25,920。若真按三班，车缺口从 5,220 降到 **0** | 问客户；或改 `config.py` 的 `SHIFTS_OVERRIDE` |
| **A2** | 阀体A 的「铣（CNC-03）」**严格点名**，CNC-03 停机 → 阀体A 全拦 | 若允许走 CNC-01/02，阀体A 3 单（120 件）可排，铣负荷从 8,600 升到 **15,800**，铣缺口从 0 变 **4,280**。**结论反转** | **Q2** |
| **A3** | 磨工序「磨（GRD-01）」**严格点名**，GRD-02 用不上 | 若视为组，磨容量 5,760 → 11,520，缺口 6,590 → **2,180**（含 C3）。**这是最大的一个变量** | **Q6** |
| **A4** | 换型/调机时间**不建模** | 实际完工会比排程晚 **10~30%**（机加工厂经验值），风险清单偏乐观 | 无法验证，写进交接说明 |
| **A5** | 工时按工艺表标准值，**不考虑效率波动** | 同上；新手操作可能慢 20~50% | 同上 |
| **A6** | 人员资质**不建模**（人人能干所有机台） | 若某台机只有特定人能开，实际产能低于模型 | 同上 |
| **A7** | 「尽快」= **无硬交期但最高优先级** | 若客户实际有隐含期限（如"本周内"），风险清单会漏报 | **Q3** |
| **A8** | 产品名是**产品族**，同族工时相同 | 若同族有多规格且工时不同，排程时长全错 | 无数据，写进交接 |
| **A9** | 全厂班次一致（08:00–24:00 两班），**日历轴统一** | 若出现三班机台混排，日历轴需改为分段轴，`calendar.offset_to_dt` 要重写 | A1 成立时安全 |
| **A10** | 允许**跨日不打断加工**（如 22:00 干到次日 10:20） | 若要求每天 24:00 必须停机，跨日工序会被切开，makespan 变长 | 无明确要求，**需确认** |
| **A11** | C3 的「间隔」按**解读 a**（车完工→磨开工的等待 ≤30min） | 若实为解读 c（完工之差），磨须延后 5 min 起，H5 表达式要改 | **Q7** |
| **A12** | 「先做一半」= 本周排 **17.5 件** | 若客户要求整数（18 件或拆成两单 17+18），排程表数字要改 | **Q5** |
| **A13** | `HD-2026-106` 出现两次按 **两单都排**（`-R2`） | 若判定为误录，法兰D 负荷少 3,800 min | **Q4** |

## ⑦ 验收标准（可测的 3~5 条，不用"良好""友好"这类词）

任务书要求：**能被第三方照着测**。

| # | 验收项 | 怎么测 | 判据 |
|---|---|---|---|
| **V1** | 校验器 0 违反 | 用客户台账跑一遍，看体检/校验输出 | H1~H4 全 PASS，H5 全 PASS 或明确 SKIP |
| **V2** | 校验器能抓撞机 | 手动改 `sched.json`，让两个工序同机台同时间，重跑 checker | 必须报 `H4 撞机`，且指出机台与时间 |
| **V3** | 工时不搞错单位 | 抽 `HD-2026-101`（阀体A 40 件），手算 `180 × 40 = 7,200 min` | 程序输出 `duration` 之和 = 7,200，逐位一致 |
| **V4** | 体检报告够全 | 打开体检报告，数类别 | ≥8 类，其中 ≥3 类标「需客户确认」 |
| **V5** | 换数据能跑 | 复制台账 → 删 2 行 → 改 1 个数量 → 改 1 个交期为文字 → 重跑 | 不报错，输出随之变化，且变化方向合理 |
| **V6** | 风险清单能反查 | 抽 2 条风险，按「卡在哪台机 + 哪个工序」回排程表查 | 能查到对应工序，且该工序确实是完工最晚的那道 |
| **V7** | 前后端全流程 | 浏览器上传 → 生成 → 下载 | ≤5 秒；四个页签都能看；下载的 xlsx 能打开 |
| **V8** | 异常有中文提示 | 上传一个 `.txt` 文件 | 页面显示「请上传 .xlsx 文件」，不白屏 |
