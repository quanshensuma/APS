# 附录 D · C3 流水约束专章

> 客户明确要求：「**阀芯C 里的备注意思是两道工序之间的间隔不能超过 30 分钟**」
> 这条是本项目**唯一一条来自客户的定量约束**，也是技术上最重的一条。
> 本附录把它的语义、算术、实现、与产能的闭环讲透。

---

## D0. 为什么单独一章

三条理由：

1. **它不是 PPT 四条硬约束里的任何一条**。PPT 第 12 页只有「不重不漏/机器对/不倒序/不重叠」，C3 是**第五条（H5）**。
2. **它和产能结论直接耦合**。不把它算进产能，磨床缺口会低估 2.6 倍（见 §D4）。
3. **它的语义有三种解释，其中一种无解**（见 §D1）。猜错会让整条约束不可行。

## D1. 语义：三种解读，一种无解

客户原话（逐字）：

> 阀芯C 里**的备注意思**是**两道工序之间的间隔**不能超过 30 分钟。

### D1.1 台账里的对应原文

`工艺路线!H5`（阀芯C 那一行的备注）：

> **磨是瓶颈，别排太散**

客户是对这句**口头备注**做量化解释。所以这条约束的业务意图是：
**零件在车完到磨之间不能放太久**（减少在制品等待、避免磨床被切得太碎）。

### D1.2 三种数学形式

| 解读 | 形式 | 业务含义 | 可行性（车 40 / 磨 35 min/件） | 采纳 |
|---|---|---|---|---|
| **(a)** 前道完工 → 后道开工的**等待** | `0 ≤ start(磨) − end(车) ≤ 30` | 零件车完多久后上磨床 | ✅ 可行 | ✅ **采用** |
| (b) 两道工序**开工**之差 | `0 ≤ start(磨) − start(车) ≤ 30` | 两工序同时开工？ | ❌ **无解** | ❌ |
| (c) 两道工序**完工**之差 | `0 ≤ end(磨) − end(车) ≤ 30` | 两工序几乎同时完工 | ✅ 可行，但磨须延后 5 min | 备选 |

### D1.3 解读 (b) 为什么无解（这是排除它的硬理由）

车工序单件工时 **40 min**。若要求 `start(磨) − start(车) ≤ 30`：

- 对**同一件**零件，磨必须在车开工后 30 min 内开工
- 但车单件就要 40 min，**磨物理上不可能在车完工前开工**（H3 也禁止）
- 且 40 > 30，**连"车一开工磨就开工"都不满足**

**→ 解读 (b) 对整批都无解，不是"难排"，是数学上不可能。**

所以客户的意思**不可能是 (b)**。剩下 (a) 和 (c)。

### D1.4 (a) 与 (c) 的差别（很小但影响代码）

| | (a) 等待 | (c) 完工之差 |
|---|---|---|
| 形式 | `start(磨) − end(车)` | `end(磨) − end(车)` |
| 磨紧接车开工（gap_a=0）时 | 满足（gap_a=0 ≤30） | `end(磨) = end(车) − 5` → gap_c = **−5** → **违反** |
| 要满足 (c) 需 | gap_a ∈ [0,30] | gap_a ∈ [5,30]（磨延后 5 min 起） |
| 业务直觉 | 「车完别放太久」 | 「两道一起完工」 |

**本设计采用 (a)**，理由：

1. 「工序间等待时间」是制造业连续流的标准口径（`maximum time lag`）
2. 与「别排太散」的业务意图一致 —— 关心的是**在制品等待**，不是完工同步
3. (c) 要求磨精确延后 5 min，在瓶颈机上无谓损失产能

**→ 但必须问客户（Q7）。切换成本低：`--flow-interp c` 改一个表达式 + gap 候选集去掉 0。**

## D2. 约束形式化

### D2.1 常量（来自台账，逐字核）

| 项 | 值 | 出处 |
|---|---:|---|
| 阀芯C 车单件工时 | 40 min/件 | `工艺路线!B5` = `车（LAT）40` |
| 阀芯C 磨单件工时 | 35 min/件 | `工艺路线!C5` = `磨（GRD-01）35` |
| 最大间隔 | 30 min | 客户原话 |
| 磨机台 | GRD-01（**点名**） | 同上 |

### D2.2 两笔订单

| 单号 | 数量 | 交期 | 备注 |
|---|---:|---|---|
| HD-2026-103 | 120 | 无（「客户催，越早越好」） | priority 5 |
| HD-2026-104 | 80 | 2026-11-14 | |

### D2.3 硬约束

```
对每个子批 lot（同一订单内的一个批）：
  0 ≤ start(磨, lot) − end(车, lot) ≤ 30
```

**注意范围**：约束是**子批内**有效，不是跨子批。

- 批内：第 i 件的车完工 → 第 i 件的磨开工 ≤ 30
- 批间：可以有任意长的断档（这是拆批的价值所在）

## D3. 两种口径的可行性

### D3.1 口径①：件级严格连续（每件单独满足）

```
单件节拍 = max(车 40, 磨 35) = 40 min/件
总跨度   = 200 件 × 40 min = 8,000 min = 8.33 天（单台磨口径）
单台磨窗口 = 5,760 min（6 天 × 960）
→ 超窗 2,240 min = 2.33 天
```

**结论：件级严格连续 + 单台磨 = 物理不可行。**

> 这里"单台磨口径"是因为磨工序**点名 GRD-01**（见主文档 §3.2）。
> 即使允许 GRD-01/02 两台并行，件级连续要求**同一件的车和磨必须相邻**，
> 而磨床还要接其他产品的活，两台也不够（见 §D4.2 的 P3 口径）。

### D3.2 口径②：子批流水（批内连续、批间可断）

**拆批规则**：

```
lot_size = L
批数 = qty / L
批内：20 件连续流动，件间磨比车快 5 min → 磨床需干等
批间：无约束，可插入其他产品
```

**磨床空等的来源**（这是最容易漏算的部分）：

```
第 1 件：磨要等车加工完 40 min 才能开工        → 空等 40
第 2~L 件：每件磨比车快 5 min，磨要等它车完   → 空等 (L−1) × 5
单批总空等 = 40 + (L−1) × 5
全部空等   = 单批空等 × 批数
```

**逐 lot_size 实算**（`_复算2` D 节 / `_复算3` E 节，全部可复跑）：

| L | 批数 | 单批车完跨度 | 单批磨完跨度 | 单批空等 | **全部空等** | 磨有效容量(1台) | **磨总缺口** |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 10 | 20 | 400 | 435 | 85 | **1,700** | 4,060 | **8,290** |
| **20** | **10** | **800** | **835** | **135** | **1,350** | **4,410** | **7,940** |
| 40 | 5 | 1,600 | 1,635 | 235 | **1,175** | 4,585 | 7,765 |
| 100 | 2 | 4,000 | 4,035 | 535 | **1,070** | 4,690 | 7,660 |
| 200 | 1 | 8,000 | 8,035 | 1,035 | **1,035** | 4,725 | 7,625 |

```
有效容量 = 窗口容量(5,760) − 全部空等
总缺口   = 磨负荷(12,350) − 有效容量
```

### D3.3 关键洞察一：空等随 L 增大而【减小】

```
L=10 → 空等 1,700
L=20 → 空等 1,350
L=40 → 空等 1,175
L=100 → 空等 1,070
L=200 → 空等 1,035
```

**原因**：首件等待 40 min 是固定成本，批数越少付得越少。
`全部空等 = 批数 × 40 + (200 − 批数) × 5`

**所以「子批越小越好塞」是错的** —— 小批在**灵活性**上赢（易插入其他产品），在**产能**上输。

### D3.4 关键洞察二：L=200（整单一批）同样满足 C3

有人可能以为「只有拆批才能满足 ≤30min」。**不对**：

```
L=200（不拆批）时：
  批内第 1 件磨等 40 min  ← 这违反了吗？
```

**不违反**。因为约束是 `start(磨) − end(车) ≤ 30`：

- 第 1 件：车完工在 t=40（用 40 min 加工），磨开工在 t=40（立即开工）→ gap = 0 ✅
- 第 2 件：车完工在 t=80，磨开工在 t=75（磨比车快 5 min，磨完第1件时是 t=75，第2件车在 t=80 才完）→ 磨要等到 t=80 → gap = 0 ✅

**为什么磨要等？** 因为磨 35 < 车 40，磨每件比车快 5 min，磨会越跑越前，被迫等车。
**等的时间是「磨床空闲」，不是「零件等待」** —— 零件一到磨床就开工，gap 恒为 0。

**所以 C3 约束在 L=200 下完全满足，代价是磨床有 1,035 min 空等。**

> **这条洞察改变了设计**：C3 不需要"拆批才能满足"，拆批是为了**让磨床能插入其他产品**，不是为了满足约束本身。

### D3.5 拆批的真实价值：灵活性，不是约束满足

| 维度 | 小批（L=10~20） | 大批（L=100~200） |
|---|---|---|
| 满足 C3 | ✅ | ✅ |
| 磨床空等 | ❌ 多（1,350~1,700 min） | ✅ 少（1,035~1,070 min） |
| 能否插入其他产品的磨活 | ✅ 高（批间有缝） | ❌ 低（一旦开跑长期占磨） |
| 车床占用 | 连续占用短，易安排 | 一次性占用 8,000 min（8.33 天单台） |
| 计划员理解成本 | 高（要解释子批） | 低（一单一批） |

**本项目默认 L=20 的理由**：

```
磨是瓶颈（GRD-01 单台承担 12,350 min，缺口 6,590）。
若 L=200，阀芯C 一次性占磨床 8,035 min > 窗口 5,760，
   → 其他产品的磨工序（阀体A 3,000 + 阀体B 2,350 = 5,350 min）一周内插不进来
   → 会制造更多延期单，而不是更少
若 L=20，磨床空等 +1,350，但换来 10 个可插空隙
   → 阀体A/B 的磨活可以塞进去
```

**代价与收益**：多付 315 min 空等（1,350 vs 1,035），换 9 个额外插入点。

**→ `lot_size` 必须做成参数**（`--lot-size`），交接说明写明改法。

## D4. 与产能结论的闭环（这是最容易出错的地方）

### D4.1 三个口径必须分清

| 口径 | 磨可用机台 | 窗口容量 | C3 空等 | 有效容量 | 磨负荷 | **缺口** |
|---|---|---:|---:|---:|---:|---:|
| **P1** 严格点名（默认） | GRD-01 | 5,760 | — | 5,760 | 12,350 | **6,590** |
| **P2** 视为组（GRD-01+02） | 两台 | 11,520 | 0 | 11,520 | 12,350 | **830** |
| **P3** P2 + 计入 C3（L=20） | 两台 | 11,520 | 1,350 | 10,170 | 12,350 | **2,180** |
| **P1+C3** 严格点名 + C3 | GRD-01 | 5,760 | 1,350 | **4,410** | 12,350 | **7,940** |

**默认口径 = P1+C3 = 7,940 min。**

### D4.2 P3 的闭环算式（逐位验证）

| 步骤 | 算式 | 结果 |
|---|---|---|
| 1. 磨净加工负荷 | 阀体A 3,000 + 阀体B 2,350 + 阀芯C 7,000 | 12,350 |
| 2. 两台磨窗口容量 | 5,760 × 2 | 11,520 |
| 3. C3 造成磨床空等（L=20） | (40 + 19×5) × 10 批 = 135 × 10 | 1,350 |
| 4. 有效容量 | 11,520 − 1,350 | **10,170** |
| 5. 真实缺口 | 12,350 − 10,170 | **2,180** |
| 6. 校验闭合 | 10,170 + 2,180 | 12,350 ✅ |

### D4.3 为什么必须把 C3 空等算进去

**如果只算净加工**：

```
12,350 − 11,520 = 830 min     ← 会得出"只缺 830 min，稍微挤挤就行"
```

**计入 C3 空等后**：

```
12,350 − 10,170 = 2,180 min   ← 真实缺口是它的 2.6 倍
```

**830 min 是"乐观下界"，2,180 min 才是真实缺口。** 差 1,350 min ≈ 1.4 个工作日。

> 这一条是设计文档里最容易犯的错：把「净加工时长」当成「产能占用」。
> 在流水约束下，**磨床的空等也是被占用的时间**（它不能去干别的活）。

## D5. 算法实现（磨床优先）

### D5.1 为什么要"磨床优先"

两种思路：

| 思路 | 做法 | 问题 |
|---|---|---|
| 车床优先（直觉） | 先排车，再找磨 | 车床有 3 台、磨床 1 台。车排好了，磨接不上 → 白排，要回滚 |
| **磨床优先（本设计）** | 先枚举磨床空闲窗口，倒推车何时完工 | 一次成功率高；瓶颈资源先占位 |

**理由**：磨是瓶颈（12,350 min 压在一台上），车是富余（22,500 min / 3 台）。**先占瓶颈资源**是排程的通用原则。

### D5.2 伪码

```
FUNCTION try_place_lot(lot, timelines, fc, opts) -> bool:
    car_cands ← 可用车床列表（组内 available）
    grd_cands ← 可用磨床列表
    IF 任一为空: RETURN False

    earliest ← 该单的 release 轴分钟（材料到货）

    best ← None

    ▷ ① 枚举磨床的每一个空闲窗口
    FOR m_grd IN grd_cands:
      FOR (ws, we) IN timelines[m_grd].free_windows(min_dur=lot.grd.duration):

        ▷ ② 让磨在 ws 开工；倒推车必须何时完工
        FOR gap IN gap_candidates:            ▷ 从大到小，见下
            target_car_end ← ws − gap

            FOR m_car IN car_cands:
                s_car ← timelines[m_car].earliest_slot(after=earliest,
                                                       duration=lot.car.duration)
                IF s_car 为空: CONTINUE
                r_car ← advance(s_car, lot.car.duration)
                actual_gap ← ws − r_car.end

                ▷ ③ 必须满足 C3
                IF NOT (0 <= actual_gap <= fc.max_gap): CONTINUE

                score ← (actual_gap, r_car.start)     ▷ gap 越小越好，车越早越好
                IF best 为空 OR score < best.score:
                    best ← (score, m_car, r_car, m_grd, ws, actual_gap)
                BREAK

    IF best 为空: RETURN False

    ▷ ④ 延迟提交：确认后再占机台
    timelines[m_car].occupy(best.r_car)
    timelines[m_grd].occupy(advance(best.ws, lot.grd.duration))
    RETURN True
```

### D5.3 gap 候选集（从小到大 vs 从大到小）

**规格：从大到小试** `[30, 25, 20, 15, 10, 5, 0]`

**理由**：

- `gap=30` 给磨床 30 min 弹性去等一个空闲窗口开始
- `gap=0` 要求磨床在车完工的**那一分钟**就空出来 —— 在最忙的瓶颈机上几乎必失败

**例外**：解读 (c) 时去掉 0（因为 gap_a=0 会导致 gap_c=−5 违规），候选集改为 `[30,25,20,15,10,5]`。

### D5.4 复杂度

```
磨床候选 ≤ 2 台
空闲窗口 ≤ 每个子批 20 个
gap 候选 7 个
车床候选 ≤ 3 台
→ 单子批最坏 2 × 20 × 7 × 3 = 840 次评估
→ 10 个子批 = 8,400 次 → 毫秒级
```

## D7. 如果客户确认"磨可视为组"（Q6 答"是"）

则口径从 P1+C3 变为 P3：

| 项 | P1+C3（默认） | P3（Q6 答"是"） |
|---|---:|---:|
| 磨可用机台 | GRD-01 | GRD-01 + GRD-02 |
| 磨容量 | 5,760 | 11,520 |
| C3 空等 | 1,350 | 1,350 |
| 有效容量 | 4,410 | 10,170 |
| 缺口 | **7,940**（8.27 天） | **2,180**（2.27 天） |

**两种情形下这批订单都装不进一周**，但性质不同：

- P1+C3：**产能严重不足**，必须加机器或延期，一周内只能交一小部分

**所以 Q6 的答案直接决定项目结论的性质。** 这是必须优先问的原因。

## D9. 必须写进交接说明的三句话

1. **「阀芯C 的两道工序间隔按"车完工到磨开工的等待 ≤30 分钟"实现；如果您的意思是"两道工序完工时间之差"，请告诉我们，改一个参数即可。」**
2. **「为了满足这个间隔，阀芯C 按 20 件一批排，批和批之间可以断开，让磨床去干别的活。」**
3. **「这个约束让磨床的有效产能少了 1,350 分钟（约 1.4 个工作日），已经算进风险清单了。」**

第 3 句最关键：**让客户知道约束的代价，而不是让他以为约束是免费的。**
