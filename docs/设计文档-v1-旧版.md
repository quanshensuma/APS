## 0. 数字口径声明（先读这一节）

本文档所有产能/负荷/缺口数字**必须带口径标签**，否则无意义。因为有两个开关会改变全部结论：

| 标签 | 含义 | 影响 |
|---|---|---|
| **B1** | Q2 = 能走 CNC-01/02（阀体A 可排）+ 含 `106-R2` | 磨 12,350 min |
| **B2** | Q2 = 不能走（阀体A 全拦）+ 含 `106-R2` | 磨 9,350 min |
| **B3** | Q2 = 不能走 + 拦 `106-R2` | 磨 9,350 min、总负荷 62,800 |

**默认口径 = B1**（最保守假设：所有数据都能排，结果是"装不下"）。
若 Q2 答"不能走"，结论**反转**，详见 §5.4.0.2。

## 1. 需求基线

### 1.1 客户要的两个答案（PPT 第 7 页原话）

> ① 这周每天每台机到底干什么　② 哪几单要赶不上

**这两句是唯一的验收标准。** 所有设计取舍回到这两句。

### 1.2 他不接受的三件事

装一堆东西 / 必须联网 / 按年付费 → 决定了技术选型必须**零外部依赖、纯本地、单文件可跑**。

### 1.3 客户 2026-10-28 澄清（设计基线变更）

客户就订单表问题回复三条，**逐条转成设计决策**：

| # | 客户原话（转述） | 设计含义 | 影响面 |
|---|---|---|---|
| **C1** | 订单表格式混乱和错误，**后续会跟宏达工作人员沟通复核**，保证后续订单信息的准确性和完整性 | 数据质量问题**不由本工具承担修复责任**，本工具的责任是**穷举列出问题、拦住不能算的行**，等复核结果回填。→ 设计上要有一个**「数据闸门」**（§4.3），拦下的行不参与排程、但必须出现在体检报告 | 清洗模块、交付物 2 |
| **C2** | 交期问题，后续也会保证**交期一栏有明确的日历时间** | 交期格式问题**将被上游修掉**。→ 系统**仍必须同时支持**「纯日期」和「人话」两种输入（历史数据、以及上游万一再出错时的兜底），但**优先级降级**：从「必须问客户」降为「能自动解析就用，解析不了进闸门」 | 清洗模块、假设清单 |
| **C3** | 阀芯C 里的备注意思是**两道工序之间的间隔不能超过 30 分钟** | ⚠️ **全新硬约束**，台账里原本只写了「磨是瓶颈，别排太散」这句人话。现改为可校验的数值约束 H5。**但「间隔」有三义**（§5.4.1），本文按解读 (a)「车完工→磨开工的等待 ≤30min」落地，并列假设 A10 / 阻塞项 Q5。→ 本版**技术上最重的一条变更**（§5.4） | 排程模型、校验器、甘特图 |

> **C3 的连锁后果**：工艺表备注「磨是瓶颈，别排太散」不是一句提醒，而是一条**流水线同步约束**。它把阀芯C 的车和磨绑定成一对，磨床的自由度被大幅压缩。量化见 §5.4.2。

## 2. 系统架构

### 2.1 数据流（严格对应 PPT 第 10 页）

```
                    ┌─────────── AI 只在这两端 ───────────┐
                    ↓                                    ↓
  ┌────────┐   ┌──────────┐   ┌──────────┐   ┌────────┐   ┌──────────┐
  │ 台账    │→ │ 清洗      │→ │ 实例生成  │→ │ 排程    │→ │ 交付      │
  │ .xlsm  │   │ + 数据闸门│   │ 订单→工序 │   │ 启发式  │   │ 表/图/风险│
  └────────┘   └──────────┘   └──────────┘   └────────┘   └──────────┘
                     │                              ↓
                     │                        ┌──────────┐
                     └───────────────────────→│ 校验器    │ 四条硬约束 + C3
                          （独立进程，          │ 纯程序    │ 0 违反才放行
                            不经过 AI）         └──────────┘
```

**中间三步（清洗→实例→排程）与校验器全部是普通程序。** AI 只负责：读需求、写解释、写交接说明。

### 2.2 模块划分

| 模块 | 文件 | 职责 | 依赖 |
|---|---|---|---|
| 配置 | `config.py` | 日历常量、机台主数据、产品路线、运行参数 | 无 | [A1](设计/附录A-模块函数规格.md) |
| 日历 | `calendar.py` | 分钟 ↔ 工作日历互转、班次推进 | 无 | [A2](设计/附录A-模块函数规格.md) / [B1](设计/附录B-核心算法伪代码.md) |
| 清洗 | `clean.py` | 读 xlsm → 规范化 → 数据闸门 → `clean.json` | openpyxl | [A3](设计/附录A-模块函数规格.md) |
| 实例 | `model.py` | `clean.json` → 工序列表（Operation[]），含子批拆分 | 无 | [A4](设计/附录A-模块函数规格.md) |
| 排程 | `schedule.py` | Operation[] → 机台+起止（含 C3 流水） | 无 | [A5](设计/附录A-模块函数规格.md) / [B2](设计/附录B-核心算法伪代码.md) |
| 校验 | `verify.py` | 五条约束逐条报告，独立进程 | 无 | [A6](设计/附录A-模块函数规格.md) / [B3](设计/附录B-核心算法伪代码.md) |
| 渲染 | `render.py` | 排程表 xlsx / 甘特图 html / 风险清单 xlsx | openpyxl | [A7](设计/附录A-模块函数规格.md) |
| 入口 | `main.py` | 串联、CLI、场景预设、selftest | 以上全部 | [A8](设计/附录A-模块函数规格.md) |

**模块依赖方向**（单向，禁止反向 import）：

```
config ← calendar ← model ← schedule
                        ↓
                     verify        （只读 JSON，不 import schedule）
                        ↓
                     render ← main
```

**硬规则**：`verify.py` **只能** import `config` 和 `calendar`。它必须能只看 `schedule.json` + `clean.json` 就完成校验。这是「校验器独立」的技术保障（PPT 第 12 页）。

**分层原则**：`clean → model → schedule → verify` 每层只吃上一层产物，**层间用 JSON 落地**。这样排程出错时可以直接拿 `clean.json` 重跑，不用再碰 Excel。

## 4. 清洗与数据闸门

### 4.1 规范化规则（按 `项目规划.md` §2 的 11 类）

| # | 坑 | 规则 | 需要复核？ |
|---|---|---|---|
| 1 | 分钟/件 vs 分钟/批 | `duration = min_per_unit × qty` | 否（结构性问题） |
| 2 | 阀体A 铣削点名 CNC-03 | 保留 `pinned=CNC-03`；该机 `status=down` 时**整单进闸门** | **是（Q2）** |
| 3 | 交期文字 | 「尽快」→ `priority=5` + `due=null`；「月底前」→ `due=2026-11-30` + `warn`；空 → `due=null` + `priority` 取备注 | 视情况（C2 后上游会修） |
| 4 | 单号三写法 | 正则归一：`^(HD)?[-_]?(\d{4})[-_]?(\d+)$` → `HD-{年}-{序}`。纯数字 `104` → `HD-2026-104` | 否（可确定推断） |
| 5 | 单号重复 | 同号不同量 → 后者加 `-R2` 后缀，**不合并**；**默认正常参与排程**（口径 B1/B2），仅在体检报告标"待复核" | **是** |
| 6 | 数量空白 | 进闸门 `blocked` | **是** |
| 7 | 「先做一半」 | `split: {this_week: 17.5, next: 17.5}` | **是（数量取整）** |
| 8 | 设备不可用 | `down` / `idle` / `outsourced` 三态区分，见 §4.2 | **是（Q1）** |
| 9 | 机台组 vs 点名 | `pinned` 字段区分 | 否 |
| 10 | 备注业务规则 | 关键词匹配 → 优先级 / `release` / 拆批 | **是** |
| 11 | 日期四格式 | `dateutil` 兜底解析 + 手工正则表 | 否 |

### 4.2 设备状态三态（关键设计）

台账里三种「不能直接用」的状态含义完全不同，**必须分开处理**：

| 状态 | 台账原文 | 语义 | 排程处理 | 校验器报错级别 |
|---|---|---|---|---|
| `down` | 停机维修（11/8 起） | 暂时不可用，有恢复时间（但未给） | **排除**。点名到它的任务 → 进闸门 | `error`（排到 = 严重违规） |
| `idle` | 闲置 | 物理可用但未启用，需客户许可 | **默认排除**；`--enable-idle` 参数开启 | `warning`（提醒未启用） |
| `outsourced` | 外协，不计本厂 | 不在本厂排产 | **排除**，不进调度池 | 不报（正常） |
| `available` | 在用 | 正常可用 | 进调度池 | — |

> 设计要点：`idle` 与 `down` 的区别在于**「能不能问一次就变成可用」**。`GRD-02` 是 `idle`，所以 Q1 一确认就能开；`CNC-03` 是 `down`，得等维修。这个区分直接决定 §7 的敏感性分析怎么算。

### 4.3 数据闸门（Data Gate）—— C1 的落地

**设计原则**：不猜。算不了的行不许参与排程，但**必须出现在体检报告里，并带上定位坐标**。

```
读入一行 → 规范化 → 完整性能算吗？
                       ├─ 能 → orders（参与排程）
                       └─ 不能 → blocked（附带 locator + 原因 + 建议动作）
```

**闸门的三个输出通道**：

| 通道 | 内容 | 去向 |
|---|---|---|
| `orders` | 可排的订单 | 进排程 |
| `blocked` | 算不了的订单 | `02_数据体检报告.md` 的「待复核清单」 |
| `warnings` | 能排但有疑问 | 排程结果里打星标 + 风险清单备注 |

**当前台账触发的闸门项（3 条）**：

| 单号 | 位置 | 原因 | 建议动作 |
|---|---|---|---|
| `HD-2026-110` | 订单!F12 | 数量为空，备注「等客户确认」 | 复核回填数量 |
| `HD-2026-106`(第二行) | 订单!A14 | 与 A8 单号重复，数量不同（25 vs 40） | 确认是否 `-R2` 追加单（**默认按 -R2 参与排程**，计入负荷；若复核判定误录需重跑，影响 3,800 min） |
| 阀体A 全部 3 单 | 工艺路线!D3 | 铣削点名 `CNC-03`（停机） | 确认能否走 CNC-01/02（Q2） |

> 第 3 条是**产品级**闸门：一条路线不可行，所有该产品的订单都拦住。这也是为什么 Q2 没回答前，阀体A 的 3 张单（120 件）整体状态是 `blocked`。

### 4.4 C2 的落实

客户说「后续保证交期有明确的日历时间」。系统行为：

1. **优先**走标准日期解析；
2. 解析不了才走人话映射（`尽快`→priority 5、`月底前`→月末）；
3. 两者都失败 → 进闸门，**不猜**，并在体检报告里标「待上游修复」；
4. 解析成功但用了兜底值 → 打 `warn`，风险清单里注明「交期为推算值」。

**换算函数**（`calendar.py` 核心，必须过边界测试）：

```

#### 5.4.1 约束语义（C3 的三种解读）

客户原话：「阀芯C 里的备注意思是**两道工序之间的间隔不能超过 30 分钟**」。

「间隔」有三种数学解释，**文档明示采用 (a)**：

| 解读 | 形式 | 可行性（车 40 / 磨 35 min/件） | 判断 |
|---|---|---|---|
| **(a)** 前道完工 → 后道开工的**等待** | `0 ≤ start(磨) − end(车) ≤ 30` | ✅ 可行 | ✅ **采用** |
| (b) 两道工序**开工**之差 | `0 ≤ start(磨) − start(车) ≤ 30` | ❌ **无解**：车 40 > 30，磨最快也要车开工后 40 min | ❌ |
| (c) 两道工序**完工**之差 | `0 ≤ end(磨) − end(车) ≤ 30` | ✅ 可行，但磨须延后 5 min 起（35 < 40） | 备选 |

**采用 (a) 的理由**：① 「工序间等待时间」是制造业连续流的常用口径；② 与工艺表「别排太散」的业务意图一致（关心的是在制品等待，不是完工同步）；③ (b) 数学上无解，可直接排除。

⚠️ **这是解读，不是客户明示。** 见假设 A10 与阻塞项 Q5。

#### 5.4.2 H5 的产能代价（磨床真实缺口）

##### 5.4.2.1 件级严格连续不可行

阀芯C 确定量 200 件（103 的 120 + 104 的 80），车 40、磨 35 min/件：

```
单件流节拍 = max(40, 35) = 40 min/件
件级连续总跨度 = 200 × 40 = 8,000 min = 8.33 天（单台磨口径）
一周单台磨容量 = 5,760 min  → 超窗 2,240 min = 2.33 天
```

**件级严格连续 + 单台磨 → 物理不可行。**（此项与实算一致 ✅）

##### 5.4.2.2 H5 造成的磨床空等（文档 v1.0 漏算）

子批方案下，磨床并非满负荷：**首件要等车加工 40 min 才到；批内每件磨比车快 5 min，磨床必须干等**。

```
每个子批空等 = 40（等首件） + (L−1) × 5（件间间隙）
```

| 子批 L | 批数 | 单批车完工跨度 | 单批磨完工跨度 | 单批空隙 | **全部空隙** | 磨床有效容量(两台11,520) | **含H5真实缺口** |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 10 | 20 | 400 | 435 | 85 | **1,700** | 9,820 | **2,530** |
| 20 | 10 | 800 | 835 | 135 | **1,350** | 10,170 | **2,180** |
| 40 | 5 | 1,600 | 1,635 | 235 | **1,175** | 10,345 | **2,005** |
| 100 | 2 | 4,000 | 4,035 | 535 | **1,070** | 10,450 | **1,900** |
| 200 | 1 | 8,000 | 8,035 | 1,035 | **1,035** | 10,485 | **1,865** |

> **有效容量 = 窗口容量 − H5 空等**
> **H5 的空等（L=20 为 1,350 min）是约束的代价，不是产能。**
> 文档 v1.0 的"缺 830 min"是**不含 H5 的乐观下界**；计入 H5 后真实缺口 2,180 min，**是它的 2.6 倍**。
> 空等随 L 变化：1,700（L=10）→ 1,035（L=200），见上表。

##### 5.4.2.3 lot_size 的真实权衡（推翻"越小越好"）

v1.0 称「子批越小越好塞」并据此取 L=20 —— **该断言方向错误**（AR-1-03）。

从表可见：**空隙随 L 增大而减小**（首件等待 40 min 只付一次，批数越少付得越少）。
且 **L=200（整单一批）同样满足 H5**（批内件间间隙恒为 5 min ≤ 30），只是失去插入灵活性。

正确权衡是二维的：

| 方向 | 灵活性（能否插手/让步） | 磨床空等 | 磨床连续性 |
|---|---|---|---|
| 小批 L=10~20 | ✅ 高，随时可插入/让出 | ❌ 多（1,350~1,700 min） | 碎片化 |
| 中批 L=40 | 中 | 1,175 min | 尚可 |
| 大批 L=100~200 | ❌ 低，一旦开跑长期占磨 | ✅ 少（1,035~1,070 min） | 连贯，利于瓶颈 |

**v1 取 L=20 的理由（明确写出）**：阀芯C 是磨床 56.7% 的负荷，若一次占死磨床（L=200 需 4.18 天两台式连续），
阀体A/B 的磨工序整周插不进来，会制造更多延期单。**宁可付 1,350 min 空等，换插入能力。**

> 若客户更看重总产出而非灵活性（例如接受部分订单顺延下周），应改 L=200，缺口从 2,180 降到 1,865 min。
> **`lot_size` 必须做成可配置参数**，交接说明写明改法。

#### 5.4.3 三条可选实现路线

| 路线 | 做法 | 优点 | 缺点 | 采纳 |
|---|---|---|---|---|
| **A. 件级流水** | 阀芯C 全程单件流，车间隔 0 | 严格满足 C3，最简单 | 磨床 8.33 天全被占用，**物理不可行** | ❌ |
| **B. 子批流水** | 拆 L 件/批，批内件级连续，批间可断 | 满足 C3，磨床可让出缝隙 | 有空等代价（§5.4.2.2）；L 需权衡 | ✅ **v1 采用（默认 L=20）** |
| **C. 真·最大时滞（CP-SAT）** | `AddMaxTimeLag` 精确建模，每件独立 | 最优，磨床利用率最高 | 需 ortools（~60MB） | ⏸ v2 |

> v1.0 写「路线 B 是**唯一**可行做法」不准确 —— L=200 整批亦可满足 H5（§5.4.2.3），只是灵活性差。已改为"v1 采用的权衡点"。

#### 5.4.4 v1 的具体实现（路线 B）

```
1. 把订单按 lot_size=20 拆成子批（103 → 6 批，104 → 4 批）
2. 对每个子批 l（按优先级/交期排序）:
   a. 排车工序：占车床 [t, t + L×40]，车床空闲且能连续
   b. 求 gap（AR-1-13 修订，不再固定取 0）：
      for gap in [30, 25, 20, 15, 10, 5, 0]:      ← 从大到小，优先大弹性
          若 磨床在 [end(车)+gap, end(车)+gap + L×35] 完全空闲:
              取该 gap，break
      全失败 → 该子批 unplannable
   c. gap 越大 = 磨床等得越久才有空 → 越容易塞进碎片；gap=0 兜底（要求磨床立刻可用）
3. 子批之间不要求间隔，可任意顺序排
```

> **为什么从大到小试**：gap=30 给磨床 30 min 弹性去等一个空闲窗口的开始，gap=0 则要求磨床在车完工的**那一分钟**就空出来 —— 后者在最忙的瓶颈机上几乎必失败。
> v1.0 的注释「取 gap=0（最紧，最省时间）」方向错误，已删除。

#### 5.4.5 校验器如何验 H5

```
for 每个阀芯C 订单:
  for 每个子批 l:
    if 子批未排入（unplannable / not_scheduled_in_horizon）:
        report SKIP: f"[H5-SKIP] {l} 未排入，无法校验流水"
        计入未排入清单;  continue
    gap = start(磨_l) - end(车_l)

```

**规则：未排入 ≠ 通过。** 报告首页必须显示「已校验 X 个子批 / 未排入 Y 个子批」，Y>0 时风险清单必须有对应条目。

⚠️ 上式按解读 **(a)** 编写。若 Q5 确认为解读 (c)，须改为 `end(磨) − end(车) ∈ [0,30]`。


### 5.5 排程算法（v1 启发式）

**为什么不用求解器证明**：13 单 × 平均 3.77 道工序 = **49 个 Operation**，磨床 3000+2350+7000 min 集中在 2 台，是**容量受限**问题不是**组合爆炸**问题。启发式加局部调整足够，且结果 100% 可复现（客户会问「为什么这单排这天」，得答得出来）。

```
Algorithm: List Scheduling with Calendar
──────────────────────────────────────────
1. 排序订单：
   priority DESC → due ASC(空交期视为最晚但优先级最高) → qty DESC
   急单（priority=5）：HD-111, HD-103, HD-105
2. 对每个订单展开工序（点名机台则固定，组则候选集）
3. 逐工序贪心选机：
   候选机台 = {m | m.group == op.group AND m.status == available}
   若 op.pinned: 候选机台 = {op.pinned}   ← 停机则整单 blocked（§4.3）
   四点取最优：
     earliest_start = max(prev_end, machine_free, order.release)
     选 earliest_start 最小的机台；并列时选当前负载最小的
4. advance() 按工作日历推进，跨班次/跳周日
5. 阀芯C 走 §5.4.4 的流水子批特判
6. 输出 Schedule[]
```

**复杂度**：O(orders × ops × machines) ≈ 49 × 3 = **147 次评估**，**毫秒级**。

**后处理（局部改进）**：贪心后做一轮「延期单优先插入」——对已延期的订单，尝试把它前移到任意更早的空档，若能减少延期天数就接受。最多迭代 3 轮，避免震荡。

### 5.6 敏感性与场景对比（为什么必须做）

因为 §4.2 的 `idle`/`down` 是**待确认项**，而它们直接决定可行性。排程器必须支持参数化切换，跑出对比表：

| 场景 | 参数 | 磨缺口 | 车缺口 | 铣缺口 | 说明 |
|---|---|---:|---:|---:|---|
| S1 基准 | 默认（GRD-02 闲置、CNC-03 停机） | **6,590** | 5,220 | 4,280 | 最坏 |
| S2 开闲置磨 | `--enable-idle` | **830**(不含H5) / **2,180**(含H5,L=20) | 5,220 | 4,280 | 磨改善，**车/铣不变** |
| S3 磨全开 + 铣恢复 | `--enable-idle --enable-cnc03` | 830 / 2,180 | 5,220 | **0** | 铣解决，**车仍是瓶颈** |
| S4 极端 | 全开 + 3 班车床（违 A1） | 830 / 2,180 | **0**（容量 25,920 > 负荷 22,500） | 0 | 上界参考，仅作对比 |

> **关键观察**：`--enable-idle` 只对磨有效（车床无闲置机）。
> S4（3 班车床，违反假设 A1）能让车床缺口归零、铣床（若恢复 CNC-03）归零，
> 但**磨的 2,180 min 缺口（含 H5）在任何参数组合下都消不掉** —— 因为磨只有 2 台且没有第三台可加。
> 所以：**磨床缺口是这批订单一周内装不下的唯一硬性原因**，车床/铣床缺口是可谈的。

**这张表是给客户看的决策依据**：它回答「我多开一台机器能提前几天」——比任何排程表都有说服力。

  [H5] HD-2026-103 子批L2 车间隔 55 min > 30
  [H5-SKIP] HD-2026-104 子批L4 未排入（磨床无 ≤30min 窗口），无法校验流水
────────────────────────────────────────
结果：❌ 不可交付（H5 未过 + 2 子批未排入）
```

**未排入 ≠ 通过。** 报告首页必须同时显示「已校验 X / 未排入 Y」，Y>0 时风险清单必须有对应条目。

**硬性规则：五项全过才允许渲染交付物。** `main.py` 里在这一步直接 raise，不给自己开后门。

## 7. 交付物设计

| # | 交付物 | 文件 | 关键设计 |
|---|---|---|---|
| 1 | 需求确认单 | `01_需求确认单.md` | 客户 3 条澄清 C1/C2/C3 + 待回答 Q1~Q5 |

### 7.1 甘特图设计要点

- **单文件 HTML**：数据以 `<script>const SCHEDULE = {...}</script>` 内联，不引任何 CDN
- 行 = 机台（9 台在用），列 = 6 个工作日 × 16 小时
- 色块 = 订单，颜色按产品区分
- **磨床行高亮加粗** —— 它是瓶颈，视觉上要第一眼看到
- 阀芯C 的车/磨用**连线**标注流水关系（体现 C3）
- 延期风险订单色块加红色边框
- 打印样式：`@media print` 下 A3 横向一页

### 7.2 风险清单的关键字段

客户要的不是「哪单晚」，是「**卡在哪台机**」—— 因为知道卡哪台，他才知道去哪儿想办法。

```
单号 | 类型 | 交期 | 预计完工 | 差几天 | 卡在哪台机 | 卡在哪个工序 | 建议动作
HD-101      | 延期       | 11-10 | 11-12 | +2    | GRD-01 | 磨   | 启用 GRD-02 / 协商
HD-108      | 未排入本周 | 11-30 | —     | —     | —      | —    | 顺延下一窗口（交期在窗口外）
HD-103-L4   | 排不进     | 无    | —     | —     | GRD-01 | 磨   | 调整 lot_size / 增加磨床
```

**「类型」列是必需的**（AR-1-07）：
- `延期`：已排入且完工 > 交期 → 真延期，要报给客户
- `未排入本周`：交期在窗口外的单没排进本周 → **不算延期**，只提示顺延
- `排不进`：受 H5/产能限制无法安排 → 单列，需决策

不区分类型会把 6 张窗口外订单（106/106-R2/108/109/112/113）误报为延期。

### 7.3 交付物模板与质量检查

七件交付物的**完整填充模板**（章节、字段、措辞、示例、脚注）见 [附录 E](设计/附录E-交付物模板.md)。
包括：
- `01_需求确认单.md`：三件事 + C1/C2/C3 落实 + Q1~Q5 + 不做清单 + 签字栏
- `02_数据体检报告.md`：11 类坑逐行定位 + 闸门清单 + 复核跟踪表 + 负荷核算
- `03_周排程表.xlsx`：每机台一页 + 汇总页的字段与打印设置
- `04_甘特图.html`：完整 HTML 骨架与视觉规则
- `05_交期风险清单.xlsx`：四种类型的建议动作模板 + 脚注固定写法
- `06_交接说明.md`：**「不能做什么」必须写在前面** + A1~A12 + 重跑步骤 + 故障速查
- `07_校验报告.txt`：首行口径标签 + 末行结果标记 + 签字栏

### 7.4 3 分钟演示脚本（PPT 第 22 页）

交付时必须能讲完，掐表。

| 时段 | 讲什么 | 对应材料 |
|---|---|---|
| 0:00–0:30 | 客户的问题：以前怎么排、卡在哪 | PPT p7 客户原话 |
| 0:30–1:30 | 我做了什么：拿到数据怎么处理、怎么排 | 体检报告 + 甘特图 |
| 1:30–2:30 | 结果与风险：哪几单要晚、**卡在哪台机** | 风险清单 |
| 2:30–3:00 | 局限与下一步：这版没做什么、什么条件下可信 | 交接说明 §2 |

**最后一句话（决定客户信不信）**：

> 「这版能帮你排这一周，但**换型时间和人员资质还没模型，急单重排要手工**。」

这句话不能省。省了客户会以为工具万能，出事就变成信任危机。

## 12. 关键决策记录（ADR）

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| ADR-1 | 零依赖启发式，不用 ortools | CP-SAT | PPT 要求"不装额外依赖"；49 个 Operation 规模小；可复现可解释 |
| ADR-2 | 分层 JSON 落地 | 内存直传 | 排程出错可只重跑后半段；便于人工检查中间态 |
| ADR-3 | 数据闸门而非自动修复 | 猜值填补 | C1 明确复核是客户的事；猜错会污染交期承诺 |
| ADR-4 | 阀芯C 子批流水（默认 L=20） | 件级严格流水 / 整单 L=200 | 件级需 8.33 天不可行；L=200 空等少但占死磨床 4.18 天导致其他产品插不进。L=20 换插入能力，代价 1,350 min 空等（§5.4.2.3） |
| ADR-5 | 甘特图纯 CSS 单文件 | ECharts/D3 | 客户要断网可用；单文件无 CDN |
| ADR-6 | 校验器独立进程 | 排程器内自检 | 防止排程器的错误传染给校验逻辑 |
| ADR-7 | `idle`/`down`/`outsourced` 三态分离 | 统一"不可用" | 三者的恢复成本和决策主体不同 |
