## 0. 一句话结论

**可行，且一周内能交付**——但有一个前提必须先向客户确认：**磨床 `GRD-02` 能不能启用**。这一条不确认，延期风险清单会全表爆红，工具做出来也没人敢用。

保守口径下的实数：

| 机台组 | 总工时 | 每日产能 | 需要工作日 |
|---|---:|---:|---:|
| 磨（仅 GRD-01） | 12,350 min | 960 | **12.9 天** ← 瓶颈 |
| 铣（CNC-01/02，CNC-03 停机） | 15,800 min | 1,920 | **8.2 天** |
| 车（三台按两班） | 22,500 min | 2,880 | 7.8 天 |
| 钻 | 10,838 min | 1,920 | 5.6 天 |
| 下料 | 5,112 min | 960 | 5.3 天 |

**一周可用 6 个工作日**（11/9 周一 起，周日不排）。磨 12.9 天、铣 8.2 天都超窗。
→ 启用 `GRD-02` 后磨降到 **6.4 天**，刚好卡进窗口；`CNC-03` 若能在 11/8 之后恢复，铣降到 5.5 天。
**所以：这批订单"能不能一周做完"，完全取决于这两台机器，不取决于排程算法。**

总负荷 66,600 分钟 ≈ **1,110 机时**，13 张有效订单。

## 2. 数据体检：11 处坑，逐条定位

按 PPT 第 17 页的分类框架，但每一条都落到具体行。

### 2.1 【高危】分钟/件 vs 分钟/批

工艺表写「单件工时合计 180」。若把它当**每批**工时，120 件阀体A 只算 180 分钟而不是 21,600 分钟 —— 总量差 **30 倍**，风险清单一条都不会报。

**处理**：`时长 = 单件工时 × 数量`。交付前手工核算一单对账（PPT 第 24 页第一条翻车点）。

### 2.2 【致命】阀体A 的铣削被点名死锁在停机的机器上

`阀体A → 铣（CNC-03）60` —— 是**点名某台机**，不是组。而 CNC-03 **11/8 起停机**，恢复日期数据里没有。
可阀体A 有 3 张单、共 120 件：`101`(40) / `102`(60) / `111`(20)。

**严格按台账执行 → 阀体A 一张都排不出来。**
**处理**：必须问「阀体A 的铣能不能走 CNC-01/02」。问不到就写进风险清单头条 + 假设 A2，不能自己偷偷改。

> 这一条和 `法兰D → 铣（CNC）` 恰好相反 —— 后者不带编号，是**机台组**，三台里任选。同一个表里两种含义混用，解析器必须区分（PPT 第 8 页第 ④ 点正是指这个）。

### 2.3 交期是「一列人话」，不是一列日期

| 行 | 单号 | 交期原文 | 解析结果 |
|---|---|---|---|
| r5 | HD-2026-103 | **（空）** | 无交期 + 备注「客户催，越早越好」→ 按最急处理 |
| r7 | HD-2026-105 | **尽快** | 无日期 + 「材料 11/8 才到」→ 11/9 为最早开工 |
| r10 | HD-2026-108 | **月底前** | 2026-11-30（兜底，需确认口径） |
| r4 | HD-2026102 | 11月12日 | 2026-11-12 |
| r3 | HD-2026-101 | 2026/11/10 | 直接可用（同行的 `2026/11/3` 是**接单日期**，别读串列） |

注 1：`r1` 标题写「2026-11-08 计划员小李整理」，而台账里最早交期是 11/10。**排程原点必须晚于 11/8**，PPT 定为 **11/9 周一 08:00**。

注 2：`2026/11/3` 这类在 `openpyxl` 里读出来是**字符串**而非 `datetime`，`2026.11.4` 同理 —— 清洗器必须统一 `dateutil` 解析，不能靠 `isinstance(x, datetime)` 判断。

### 2.4 单号三种写法 + 一行重复号

- `HD-2026-101`（标准） / `HD2026102`（缺连字符） / `104`（只有数字）
- **`HD-2026-106` 出现两次**：`r8` 数量 25，`r14` 数量 40 备注「第二轮追加」

**处理**：104 → `HD-2026-104`；102 → `HD-2026-102`。重复号**不能合并**（交期相同但数量不同，是两次下单），规范为 `HD-2026-106` + `HD-2026-106-R2`，并在需求确认单里注明。

### 2.5 数量空白 + 备注里的拆批

| 单号 | 问题 | 处理 |
|---|---|---|
| HD-2026-110 | 数量空，备注「数量等客户确认」 | **剔出首版排程**，单独列「待定单」，不猜 |
| HD-2026-113 | 数量 35，备注「先做一半，剩下的下周」 | 本周按 **17.5 件** 排，下半批挂下周 |
| HD-2026-102 | 备注「和李工确认过，和上批一起做」 | 与 101 同产品同客户，可合并为**一个批次**减少换型（v1 只记录建议，不自动合并） |

### 2.6 备注里藏着的五条业务规则

| 单号 | 备注 | 转化成的约束 |
|---|---|---|
| HD-2026-111 | 急单，张工说的 | 优先级 5（最高） |
| HD-2026-103 | 客户催，越早越好 | 优先级 5 |
| HD-2026-105 | 材料 11 月 8 日才到 | **物料约束**：下料工序 release = 11/8 |
| HD-2026-113 | 先做一半 | 拆批，本周 17.5 |
| HD-2026-102 | 和上批一起做 | 批次合并建议 |

### 2.7 工期字段缺失

`HD-2026-109` 接单日期空白 —— 不影响排程（排程只用交期），但**数据体检报告里要列出来**，因为按周统计接单量时它会漏。

### 2.8 设备状态三类特殊情况

`CNC-03` 停机 / `GRD-02` 闲置 / `HT-01` 外协 —— 三者都**不能直接当可用产能**，但含义不同：停机是「暂时不可用」、闲置是「可用但未启用」、外协是「不在本厂排」。校验器要能分别报错。

### 2.9 三班车床按两班算

`LAT-03` 每天 3 班，但全厂口径是 08:00–24:00 两班。**不能偷偷加产能**，写进假设 A1。

### 2.10 日期格式四种

`2026/11/3`、`2026.11.4`、`2026-11-10`、`11月12日`。`openpyxl` 读出后 `2026/11/3` 实际是**字符串**不是 datetime，要统一解析。

### 2.11 产品名是「族」不是「料号」

5 个产品（阀体A/B、阀芯C、法兰D、端盖E）是**产品族**，实际可能有颜色/规格变体但工时相同。v1 按族排，写进假设。

## 3. 产能核算：瓶颈在哪

见上方第 0 节表格。补充三点：

**（1）磨床是唯一真瓶颈。** 12,350 分钟全部压在 `GRD-01` 一台机器上。工艺表备注自己都写了「磨是瓶颈，别排太散」—— 客户是有感知的。

**（2）一周窗口内必然延期。** 6 个工作日 vs 12.9 天需求 → 至少 **6.9 个工作日缺口**。所以**延期风险清单一定会非空，这不是 bug 是事实**。工具的诚实度比"排得好看"更重要。

**（3）启用 GRD-02 是唯一解。** 6.4 天 < 6 天窗口的边界上（略超 0.4 天），基本可行；若再把 `CNC-03` 提前恢复，铣从 8.2 天降到 5.5 天，整体就能装进一周。

> 结论：**这不是一个"算法不够好"的项目，是一个"产能不够"的项目。** 工具的价值是**把缺口算准并说清卡在哪台机**，而不是假装排得下。

## 5. 技术方案

### 5.1 架构（严格按 PPT 第 10 页那条链）

```
台账.xlsm → 清洗 → 实例生成 → 排程 → 校验 → 交付
              ↑                  ↑       ↑
           规则+人工确认       启发式/CP-SAT  四条硬约束（纯程序）
```

**AI 只在两端**：开头理解需求、结尾写解释。中间三步全部是普通程序 —— 这一点是 PPT 反复强调的，也是唯一能保证可复现的做法。

### 5.2 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.11.7（已装） | 环境现成 |
| 读表 | `openpyxl 3.1.5`（已装） | 直接读 xlsm，保留格式 |
| 排程 v1 | **自研列表调度启发式**（零依赖） | PPT 要求「不装额外依赖」；13 单 × 5 工序规模小，启发式够用且 100% 可复现 |
| 排程 v2（可选） | `ortools` CP-SAT | 若要最优解。**约 60MB 依赖，需先征得同意** |
| 甘特图 | **单文件 HTML**，纯 CSS + 内联数据 | 断网双击可开，无 CDN |
| 排程表 | `.xlsx`（openpyxl 生成，设定 print_area） | 客户要打印贴墙 |
| 校验器 | 独立脚本，行程序 | 不经过 AI，同一把尺子 |

> ⚠️ 当前环境 **`ortools` / `pulp` 均未安装**。v1 先用零依赖启发式落地，v2 再看。

### 5.3 排程策略（v1 启发式）

```
1. 按优先级(急单) → 交期 EDD → 数量，排序订单
2. 逐单展开工序链，每道工序：
   a. 候选机台 = 工序指明组内的可用机台（排除停机/外协；点名则只那台）
   b. 选「最早可开工」的机台（并列时选当前负载小的）
   c. 开工时间 = max(前道完工, 该机台空闲, 物料到货)
   d. 按「可用分钟」推进，跨班次/跳周日时顺延
3. 输出每个工序的 机台/起/止
4. 校验器逐条验四条硬约束
5. 计算每单预计完工 vs 交期 → 风险清单
```

关键实现点：**时间要按「工作日历」推进，不能简单除 60**。分钟 → 日历换算需要过班次边界（08–16、16–24）和周日跳过。这是 PPT 第 13 页点名的第一个换算。

### 5.4 校验器（四条硬约束，PPT 第 12 页）

| # | 检查 | 报错措辞 |
|---|---|---|
| ① | 每道工序恰好出现一次 | 「漏排/重排：HD-xxx 工序2 出现 0 次」 |
| ② | 机台可做该工序 + 时长 = 单件工时×数量 | 「排错机器：阀芯C 的磨排到了 CNC-01」 |
| ③ | 同订单工序不倒序 | 「倒序：HD-xxx 工序3 早于工序2 完工」 |
| ④ | 同一机台时间不重叠 | 「撞机：CNC-01 在 11/9 14:00–16:00 有两个任务」 |

**0 违反才交付。** 这一条丢了，后面全白做。

## 7. 排期（对齐 PPT 六步）

| 步 | 内容 | 工时 | 阶段 |
|---|---|---|---|
| 1 | 接单：读简报，写「我理解的三件事」 | 20 min | 课堂 |
| 2 | 访谈：5 个关键问题 → 需求确认单 | 20 min | 课堂 |
| 3 | 体检：11 类坑逐条定处理（**本文件第 2 节已完成 80%**） | 40 min | 课堂 |
| 4 | 取舍：订单→工序实例映射 + 假设清单 | 30 min | 课后 |
| 5 | 构建：清洗器 → 启发式排程 → 校验器 → 三份输出 | 3~4 h | 课后 |
| 6 | 交付：3 分钟演示 + 交接说明 | 30 min | 课后 |

**注意**：第 2 步的 5 个问题里，Q1/Q2/Q3 没回答之前，第 4 步的假设清单**只能写"待定"**，不能自己编答案。这是交付可信度的根。

关键路径：`第4步(实例映射) → 第5步(排程核心)` 占 80% 工作量。甘特图和打印表是**渲染层**，只要排程数据结构对了，半天能做完。
